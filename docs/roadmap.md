# Roadmap

搬家 / 上 VPS 之后要上的东西，按优先级排。

## 待办

- [ ] **GitHub webhook 监听**：在 VPS 上起一个公开接收端，监听仓库 issue / PR 事件，收到即唤醒克劳德拉第一时间回复（替代本地定时轮询）。
  - 前提：定下 VPS / 公网端点。
  - 组件：接收端脚本（放 `scripts/`）+ 各仓库的 webhook 配置。
- [ ] **scripts/ 一键迁移脚本**：clone 本仓库后，按 `capabilities/` 还原能力、注入密钥。
- [ ] **中心实例 + SSH 隧道多端架构**：VPS 上只跑一个 DSH（web profile + ds-bot），桌面/手机通过远程访问连同一个实例，共享同一份记忆与会话。
  - 手机端：SSH 隧道 `ssh -L <本地端口>:127.0.0.1:<dsh端口> user@vps`，浏览器开本地端口访问。
  - 不装独立 APK（那样是每台各养一个我），走"一个本体、多端开门"。
  - 注意：DSH 端口不暴露公网，只走隧道；多端并发连接与鉴权待验证。
- [ ] **微信机器人路线**：体验最贴身。分三档：企业微信应用（推荐）、公众号（受限）、个人微信 hook（封号风险，不推荐主号）。
  - 架构：微信服务器 → VPS 桥接服务 → DSH → 微信 API。
  - 难点：一问一答 vs 长上下文，桥接层管上下文、排队、异步回复。
- [ ] **QQ 机器人路线（专属号 1591794404）**：用 NapCat / Lagrange 接成个人号机器人（OneBot 协议），官方 QQ 机器人平台当备选。
  - 架构：QQ 消息 → NapCat（VPS）→ OneBot HTTP/WS → 桥接 → DSH → 回复。
  - 代价：第三方协议、有封号风险（专属号，风险可控）。
